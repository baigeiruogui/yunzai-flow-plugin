## 二、加固过程中发现并修复的真实缺陷

- **所有弹窗关不掉、整页点不动**（最严重）：`.modal/.onboard` 的 `display:grid` 覆盖了 `hidden` 属性，导致全屏遮罩一直显示并拦截点击 → 加 `[hidden]{display:none!important}`。
- **运行限额未初始化**：接入并发限额时漏初始化，导致运行报 `limiter is not defined` → UI 冒烟当场抓到并修复。
- **删除不存在的流程返回 200**：SQLite 驱动未判存在性 → 改为 404。
- **节点长标签把参数值挤出卡片**：事件类型标签过长 → 缩短标签 + `.bd/.kv` 溢出约束 + 标签省略号。
- **移动端顶栏 159px 过高**（两行顶栏按钮换行堆叠）→ 窄屏工具栏单行横向滚动，降到 79px。
- 更早的功能期还修复过：SSE `done` 帧缺 `type` 致前端卡"运行中"、事件 `type` 被 payload 覆盖、`sender.userId` 提取、cacheKey 作用域、渲染目录等。

## 三、为"防复发/防误操作"补的机制

- **静态资源 `Cache-Control: no-store`**：杜绝"改了代码浏览器用旧缓存"（上述遮罩事故的同类根因）。
- **前端全局错误可见化**（error/unhandledrejection → toast），不再"点了没反应却不知为何"。
- **过期请求丢弃**：快速切换流程不会被旧响应覆盖。
- **未保存改动提醒**：dirty 标记 + 离开页面 `beforeunload` 确认，防误关丢改动。
- **恢复前自动备份**：`/restore` 先写 `data/backups/pre-restore-*.json`，防误恢复丢数据。
- **密钥加密持久化**：AES-256-GCM 落盘、主密钥独立、重启可解密、文件无明文。
- **统一脱敏**：运行快照/API/落库对敏感键打码，`secretRef` 保留引用。
- **运行时重试**：`policy.maxAttempts` 对可重试失败生效、不可重试不重试。
- **画布增量渲染**：只更新变更节点（大图加节点 ~30ms），减少重绘抖动。

## 四、已知限制 / 不做假的点

- **实机验证 = 0**：真实 NapCat/TRSS-Yunzai 联调需你的环境（填入 `config.napcat.httpUrl/wsUrl/accessToken` 即切直连；本地 OneBot 协议端点已跑通）。
- **wait/Delay 持久化检查点（§7.3）**：当前延时为内存等待（上限 2s），不做"看似支持却不可靠"的假实现，列为路线图。
- **代码节点**为"故障隔离"（独立子进程+超时+内存上限），非 OS 级安全沙箱；不可信导入代码需真实隔离。
- **结构性表单**中从源码 TypeBox 提取的部分为启发式解析，复杂嵌套类型降级（覆盖报告已分轴标注）。

## 五、结论

核心工程缺陷已修、四层自动检查覆盖关键路径、误操作有防线、破坏性操作可回滚；纯本地能防的"小问题"已基本消灭。剩余风险集中在**真实环境联调**与**少数较大特性**，需要真实条件或专门投入。
